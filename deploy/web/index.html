xeet

source

Social posts rendered to PNG without a browser, from WebAssembly, a Rust crate or the CLI.

Created by Guillermo Rauch. All credit for the original Xeet goes to him. This fork extends his interface and Rust engine to five platforms.

  • One engine, five feeds. X, Threads, Facebook, Instagram and TikTok each get their own post layout.
  • Real post data. Public links resolve through research, including profile photos, media and counts when available.
  • No screenshot browser. Open Noto fonts and a Rust rasterizer paint the PNG. Video posts render as stills; this fork does not inherit upstream’s pixel-parity certification.

Use it #

One Rust renderer, five platforms. Pass post JSON to the WebAssembly SDK to produce a PNG offline. Public links are resolved separately through research; videos become still images.

Download browser SDK · Download source · Original Xeet

Render a post

// Serve xeet.js and wasm/ from the SDK archive together.
import { render } from "./xeet.js";
const { png, report } = await render({
  platform: "threads", // x | threads | facebook | instagram | tiktok
  text: "A little thing, beautifully shared.",
  author: { name: "You", handle: "you" },
}, { width: 600, theme: "dark", dpr: 2 });
const url = URL.createObjectURL(new Blob([png], { type: "image/png" }));
document.querySelector("img").src = url;

The SDK's rendering methods are asynchronous wrappers around the Rust/WASM core. Rendering uses embedded open Noto fonts and needs no browser screenshot or network after loading. Photos must be supplied as image data.

Resolve a public link on this site

import { resolve, render } from "/xeet.js";
const { post, warnings } = await resolve("https://www.threads.com/@sharenow_today/post/Dfyjw3KjZAe");
const { png } = await render(post, { width: 600, theme: "light" });

Live resolution uses this site's API and its background research service. It may take a minute. Private, deleted or restricted posts cannot be guaranteed; missing fields are left out rather than invented.

Build the renderer

bash scripts/build.sh

The source pins the upstream Xeet commit and applies the included Rust layout modules. X keeps the original renderer. Threads, Facebook, Instagram and TikTok use platform-specific layouts. These are recreations, not certified pixel parity.

Render from the command line

node scripts/render.mjs post.json post.png dark 600
# Public-link input also requires the authenticated research CLI:
node scripts/render.mjs 'https://www.threads.com/@sharenow_today/post/Dfyjw3KjZAe' post.png

JSON rendering works locally. Live-link rendering additionally needs Python, Pillow, pillow-heif and the research CLI connection. See the source README.

API #

Rendering

await render(post, options)       // { png, report }
await explain(post, options)      // layout report
await renderRgba(post, options)   // { width, height, rgba, report }
await renderBatch(post, options)  // one rendered result per options object
await resolve(publicPostUrl)      // { post, warnings, source }; hosted API

Options and limits

Choose light or dark, width, device-pixel ratio, font scale and surface. X retains Xeet's timeline/detail behavior. The other platforms use their own single-post layouts; TikTok uses a portrait video still. Instagram and Facebook show the first carousel image. The example snapshots are public posts fetched on November 16, 2026.

Live lookup is cached for one hour and limited to 12 requests per address per hour and 150 new posts daily. It depends on the studio computer's research service. Drafts, examples and JSON rendering remain available if that service is offline.
